*The downstream Linux desktop's platform behavior, compatibility and host acceptance requirements.*

# Downstream Linux desktop application

For this downstream port, Television also supports x86_64 Linux, targeting Omarchy on Arch Linux with Hyprland/Wayland and retaining X11 compatibility. This extends the Mac-only support statement in desktop-app.md for this fork; it does not change upstream's support or release service.

The same Electron app supplies setup, authenticated connection and recovery, saved connection, disconnect, channels, pages, artifacts, embedded external pages, native links, editing, themes and shortcuts. Native Linux window controls replace Mac traffic lights. Linux shows its window immediately so Wayland can produce the first paint; Mac retains its existing ready-to-show behavior. The desktop menu exposes About Television, the installed release version, Disconnect from Server, editing/view/window commands and Quit. Linux identity is Television and `computer.telepath.television.desktop`; existing Television user data is retained.

On Linux, the Window menu offers Minimize, Maximize / Restore and Close. Maximize / Restore toggles the focused native window between maximized and its previous normal size, while keeping its server connection. With no focused window, the action does nothing. ^linux-window-menu

On Hyprland, the Window menu offers **Hide** instead of Minimize. Hide removes the owned main window from every visible monitor while keeping its process, native window, document, unsaved edits and live server connection. The action requires that owned window to be focused; with no focused window or a different focused window it does nothing. Opening Television again with the same application profile brings the original window back to its original workspace and requests focus without reloading it. Other Linux desktops retain native Minimize. ^linux-hyprland-hide

Hide preserves normal, floating and maximized window states. Unsupported fullscreen/group states, unavailable compositor support or the absence of an inactive hidden destination cause refusal before movement, with an explanation; they never select another window or close, reload or replace the original. If the original workspace was removed, restore uses the currently active normal workspace when one can be verified. A manually moved window stays on its new workspace on the next launcher activation. Manually moving it out of its holding workspace or revealing that workspace cancels the application's hidden state and original-workspace history; a later Hide records a new origin. ^linux-hyprland-placement

A failed or uncertain Hide is not reported as successful hiding. If a response is lost after a move, the application retains its ownership and reconciles the real window on later control. When compositor control is unavailable after Hide, the original content and connection stay alive and restore remains pending. A nonintrusive desktop notification explains the failure; a later launcher activation retries that exact window when control returns. Continuing control loss means restoration is failed, not guaranteed recovery. A new application process starts visibly and does not adopt an earlier process's hidden window. ^linux-hyprland-recovery

Linux window movement belongs to the native titlebar/compositor. Its framed Electron window ignores in-page CSS drag regions, so the sidebar, top-bar, setup and modal strips do not move the Linux window. This is an explicit platform exception to the frameless Mac drag interaction. Native compositor movement must be checked on a real window-manager/Omarchy session; the Xvfb page-drag driver does not establish that acceptance.

Users receive a bundled portable archive or AppImage without a Node/npm runtime requirement. A graphical installer installs the portable client into the user's applications and an Arch PKGBUILD supports distribution-managed installation. The packaged launcher selects Wayland when the session exposes it, X11 otherwise, and preserves explicit platform flags and all arguments. It never disables Chromium's sandbox or acceleration by default.

AppImage builds can update themselves when a maintainer supplies an HTTPS feed containing Linux releases. No feed means no update requests. Portable/Arch builds use distribution-managed replacement. Linux upgrade-gate instructions identify Linux replacement, preserving downloaded-update/restart presentation, rather than offering Mac binaries. Feed operation and publishing later releases are outside this lab's authority.

Acceptance launches the actual packaged application against a real token-protected server, checks persistence across relaunch and disconnect, and renders HTML, Markdown and external URL artifacts. Test both real X11 and a real Wayland compositor when available. Record physical Omarchy/Hyprland and production update-feed checks separately; no headless-compositor result proves those host checks.

## System tray

The Linux desktop client exposes a Television icon in the desktop system tray while the application runs. Activating the icon or choosing **Show Television** restores the owned main window and requests focus without reloading it. On Hyprland this uses the same original-workspace recovery as launcher activation. The menu also offers **Hide Television**, the saved server address, **Disconnect from Server**, **About Television** and **Quit**. The saved-server line does not claim live connectivity and never includes credentials. Disconnect is enabled while a connection is saved, forgets that connection and reveals the setup screen. ^linux-tray

Tray Hide targets this process's owned main window even when another application is focused. It preserves the document and connection. On Hyprland it follows the existing supported-state, ownership, placement and recovery rules; elsewhere it hides the native window. An unavailable tray does not prevent normal launch or launcher recovery. Closing the native window still quits on Linux; Quit exits rather than hiding, and removes the tray icon. Tray actions never stop the agent's server. ^linux-tray-lifecycle

## Hyprland testing

Run five actual Hide/launcher-restore cycles for Wayland and X11 on both portable and extracted AppImage entrypoints in a real isolated Hyprland session. Observe absence from all visible monitor workspaces and return to the resolved workspace independently of application state, together with original before/hidden/after captures. Mapped special-workspace windows are permitted; Electron visibility, compositor registration or renderer captures alone do not prove desktop visibility. Check same-window/document/edit/socket/profile continuity, hidden-period server updates and the production sandbox after real visible restoration. Include two profiles, lost/failed control, startup/rapid requests, missing/replaced targets, deleted workspace, manual movement/reveal and supported native states. Keep historical Electron Hide failures unchanged; Weston coverage does not accept this Hyprland mechanism. Physical input, host GPU/scaling and full verification remain separate gates.
