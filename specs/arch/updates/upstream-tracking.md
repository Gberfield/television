# Fork upstream tracking

Gberfield/television follows telepath-computer/television main as an ancestry source, and basecamp/omarchy stable releases and relevant default-branch changes as compatibility inputs. The committed manifest separates observed revisions from integrated revisions and compatibility acceptance. Observing a SHA never asserts that its code was integrated or tested. The Omarchy baseline is an observation cursor; `compatibility_reviewed_sha: null` means no compatibility acceptance is claimed. Omarchy history is never merged. ^tracking-inputs

A manually dispatched GitHub workflow discovers pending updates using read-only API calls. Relevant Omarchy paths include themes, Hyprland/Waybar configuration, package installation, launchers and update/restart commands. A changed stable release tag/commit or default branch also warrants compatibility review; divergent or truncated comparisons require review. The fork workflow has no scheduled trigger. Manual dispatch is available only after the workflow reaches fork main and repository Actions are enabled; this source configuration does not enable Actions. ^tracking-detection

A separate job can write contents and draft pull requests once the required repository capability receives specific owner approval. The manifest keeps `pr_creation_enabled: false` until then; detection reports pending updates without creating branches. It runs trusted fork-main tooling, performs Git operations without hooks, and neither installs dependencies nor executes fetched code. At most one open draft per track is prepared; existing branches and PR contents are preserved, including human edits. A create-only branch lease prevents races from overwriting a branch. A stale fork-main dispatch aborts. An orphan branch from interrupted PR creation requires owner intervention, never replacement. ^tracking-drafts

Omarchy branch identities include stable tag/commit and default-branch identity as well as its head SHA. A clean Television merge preserves upstream parents and fork workspace/lockfile versions while retaining dependency changes. A separately reviewed integration may advance the fork version when a new upstream desktop compatibility floor requires it; this is an explicit maintainer decision, never an automatic discovery or draft-preparation action. The artifact-isolation integration of upstream `a8e73fbf5eecfb27172ff5928ffb71f0c6844368` advances workspace and lockfile versions together to `1.5.4`, satisfying the `1.5.0` desktop floor without changing publishing authority. Content conflicts, invalid or nonregular/escaping manifest paths, or workflow/release identity changes (including Linux build/feed selectors) produce a report-only draft, preserving the integrated SHA until a human resolves them. The Linux feed and downstream release identity remain separate from upstream publication. Omarchy proposals report stable/head revisions and relevant changes without integration or acceptance claims. Reviewers advance its baseline and stable tag only after reviewing compatibility; observed fields alone do not suppress a pending proposal. ^tracking-integration

While the owner keeps repository Actions disabled, a maintainer validates each sync candidate manually with full canonical `npm run verify` under the [disabled-Actions fork policy](../../spec-workflow.md#^fork-disabled-actions-validation), including its final pushed head, current-target containment, provider and evidence requirements. This establishes source validation for that exact candidate; it does not require enabling or dispatching Actions. Local validation neither publishes a durable testpass attestation nor proves GitHub scheduling, token enforcement or physical Omarchy compatibility. Reports begin with `tested_sha: null`; validation does not automatically advance tested, integrated or compatibility-acceptance fields. The PR records exact-revision validation evidence, and human integration and compatibility review remain separate. ^tracking-validation

When Actions is enabled, the retained Sync validation workflow runs the existing complete CI topology only on a maintainer's manual dispatch against the selected sync branch, including drafts. Pushing a sync branch does not dispatch this additional graph. Ordinary ready-PR and shared-branch validation remains in `ci.yml` under its existing contract. Hosted sync validation uses read-only tokens, checkout without persisted credentials, actual tests rather than attested skips, and no attestation writer or deployment secrets. Publishing workflows retain their upstream repository gates.

## Local read-only discovery

The exported `discovery(manifest, read)` function supports a local coordinator through an injected GET-only GitHub adapter. Importing the module does not dispatch `main`, execute candidate tests, push branches, or create pull requests. Discovery preserves the existing pending-track and open-sync-PR deduplication rules and never advances integrated or compatibility baselines. Open PR discovery stops after ten pages of 100 results and fails explicitly when coverage is incomplete. The existing default-branch write guards still apply to the hosted `prepare` command.

Run `npm test -- local --file test/repo/upstream-discovery.test.ts` for the injected-reader discovery contracts. They are also selected by the canonical root unit suite and full verification.
