# Fork upstream tracking

Gberfield/television follows telepath-computer/television main as an ancestry source, and basecamp/omarchy stable releases and relevant default-branch changes as compatibility inputs. The committed manifest separates observed revisions from integrated revisions and compatibility acceptance. Observing a SHA never asserts that its code was integrated or tested. The Omarchy baseline is an observation cursor; `compatibility_reviewed_sha: null` means no compatibility acceptance is claimed. Omarchy history is never merged. ^tracking-inputs

A daily GitHub workflow and manual dispatch discover pending updates using read-only API calls. Relevant Omarchy paths include themes, Hyprland/Waybar configuration, package installation, launchers and update/restart commands. A changed stable release or default branch also warrants compatibility review; divergent or truncated comparisons require review. Scheduled detection becomes active only after the workflow reaches fork main. ^tracking-detection

A separate job can write contents and draft pull requests once the required repository capability receives specific owner approval. The manifest keeps `pr_creation_enabled: false` until then; detection reports pending updates without creating branches. It runs trusted fork-main tooling, performs Git operations without hooks, and neither installs dependencies nor executes fetched code. At most one open draft per track is prepared; existing branches and PR contents are preserved, including human edits. A create-only branch lease prevents races from overwriting a branch. A stale fork-main dispatch aborts. An orphan branch from interrupted PR creation requires owner intervention, never replacement. ^tracking-drafts

A clean Television merge preserves upstream parents and fork workspace/lockfile versions while retaining dependency changes. Content conflicts or workflow/release identity changes produce a report-only draft, preserving the integrated SHA until a human resolves them. The Linux feed and downstream release identity remain separate from upstream publication. Omarchy proposals report stable/head revisions and relevant changes without integration or acceptance claims. Reviewers advance its baseline and stable tag only after reviewing compatibility; observed fields alone do not suppress a pending proposal. ^tracking-integration

Sync validation runs the existing complete CI topology for sync-branch pushes and manual runs, including drafts. It uses read-only tokens, checkout without persisted credentials, actual tests rather than attested skips, and no attestation writer or deployment secrets. Validation results identify their candidate SHA; reports begin with `tested_sha: null` and the PR records external run evidence. Publishing workflows retain their upstream repository gates. ^tracking-validation
